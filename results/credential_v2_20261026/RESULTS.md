# B3/B4 修复与受控验证

日期：2026-10-26。Windows 本地 Python 3.9.13、cryptography 46.0.7；完整版本和源文件哈希见 metadata.json。

## 定义与修复

旧 B4 使用 `sha256(anchor + supplied_hash) == supplied_hash`，并未检查逐包 Ed25519 证据。现已删除该验证路径。

新 B3/B4 共用 HMAC 认证的凭证（身份、环境、静态锚点、公钥、状态、过期时间）和在线撤销表。信任部署的发行者密钥、公钥与锚点。B4 额外直接调用实际 `core.bsigner.BSigner` 与 `core.governance.EvidenceVerifier`：检查精确下一序号、Ed25519 签名、事件编码对应的链递推，全部通过才提交接收状态。B3 不消费逐事件证据。

旧 B3 未携带锚点；新 B3 补入静态锚点以与论文定义对齐。新实验只测 B3/B4，不将旧 B1/B2 数据混入新表。

## 结果

10条基础序列，每条5包；每个场景用全新接收端，B3/B4共享同一批签名包。每条攻击序列先提交前2个正常包，再注入攻击，随后继续提交正常包；永久撤销场景不恢复权限。

| 场景 | B3 | B4 |
|---|---:|---:|
| 合法序列，接受包数 | 50/50 | 50/50 |
| 原样旧包重放，拒绝次数 | 0/10 | 10/10 |
| 修改事件资源字段、保留原证据，拒绝次数 | 0/10 | 10/10 |
| 修改逐包签名，拒绝次数 | 0/10 | 10/10 |
| 相同身份跨容器提交，拒绝次数 | 10/10 | 10/10 |
| 在线撤销后提交，拒绝次数 | 10/10 | 10/10 |
| 修改凭证锚点、不重签凭证，拒绝次数 | 10/10 | 10/10 |

B4 的前3种攻击分别由序列、事件链匹配、签名检查拒绝。所有拒绝保持接收状态不变。重放、事件篡改、签名篡改三个场景的后续合法包各接受30/30；跨容器及凭证篡改后回到合法上下文也各接受30/30。每配置所有正常提交合计320/320通过。

总计140个序列运行、760次包提交。60项核心/治理/凭证测试通过；其中新增凭证测试19项。独立复核器未导入核心验证实现，使用保存的公钥、锚点、事件和签名核验380次B4提交的密码条件与状态迁移，并复算两配置的汇总。凭证HMAC密钥未保存，独立复核不声称重新认证凭证外壳。

## 复现

从 experiments 目录执行（输出目录必须尚不存在）：

```powershell
& D:\Anaconda\python.exe -B rq3/dct_vs_jwt.py --output-dir results/credential_v2_repeat --sequences 10
& D:\Anaconda\python.exe -B scripts/verify_credential_results.py results/credential_v2_repeat
& D:\Anaconda\python.exe -B -m pytest tests/test_credential_ablation.py tests/test_governance.py tests/test_bsigner.py -q -p no:cacheprovider
```

随机密钥和锚点每次重新生成，预期协议行为相同，签名原始字节不要求相同。

## 结论边界

证明当前实现可以接受合法序列、检测所测重放和篡改，并在拒绝后保留正确状态。不证明行为链优于独立签名加序号方案，不证明观测端提供的事实真实，不测持久化重启、防回滚、多节点、eBPF、LLM或操作阻断延迟。本结果可替换有缺陷的链验证证据，但需要论文同步修改配置说明、场景、样本量和结论。
